# WrathPrivateHotbar 2.0.10.0（WPH210）

FF14の通常ホットバー（HB1～HB10）からWrathComboを使う1本を選びます。選択した元のHBを隠し、同じ12枠を疑似ホットバーで表示・操作します。

v2.0.5.105からの変更点と処理方式の比較は、同梱の [CHANGELOG.md](CHANGELOG.md) に記載しています。

## 導入・更新

1. **WPH210.zip** をダウンロードし、Windowsの「すべて展開」で `ダウンロード\WPH210` に展開します。版ごとに展開フォルダーを分けます。
2. `/xlplugins` の **Dev Tools → Installed Dev Plugins** で旧版のWrathPrivateHotbarを無効にします。WrathCombo本体は有効にします。
3. `/xlsettings` の **Experimental** で **Developer Mode** を有効にし、**Dev Plugin Locations** の旧版（WPH209等）のチェックを外します。下記の新しいDLLを追加し、行のチェックをONにして保存します。展開先を変えた場合は、展開フォルダーの `copy_dev_path.cmd` で実際のパスをコピーできます。
4. `/xlplugins` の **Scan Dev Plugins** から新しいWrathPrivateHotbarを読み込み、`/wprivate config` に **2.0.10.0** と表示されることを確認します。

v2.0.5.105から初めて現行版に移る場合は、設定形式が異なるため、選択HB・発光先・配置を設定してください。WPH209の設定は引き継ぎます。

標準の展開先でDalamudに登録するDLLのフルパス

```text
C:\Users\admin\Downloads\WPH210\DevPlugin\WrathPrivateHotbar.dll
```

## 疑似ホットバーの使い方

- **枠と鍵**　通常時はバー名を表示しません。右端の鍵をクリックすると位置の固定／解除が切り替わります。解除中はアイコンまたは鍵をドラッグして移動できます。固定中もスキルを実行できます。`/wprivate show` で保存済みの位置に再表示できます。
- **スキルの間隔**　`/wprivate config` の「配置・連打」にある「横の枠間隔」「縦の枠間隔」を個別に調整できます。＋／－は0.1px刻みで、数値の直接入力もできます。48pxのアイコンを基準に0.0～24.0pxの範囲で指定し、拡大時は間隔も同じ比率で広がります。以前の間隔は縦横の両方に引き継ぎます。
- **キー文字**　「配置・連打」の「キー文字の基準位置」で左上・中央上・右上を選べます。初期値は左上です。「キー文字の横位置」「キー文字の縦位置」は48pxのアイコンを基準に－24.0～＋24.0px、0.1px刻みで独立して指定できます。横の＋で右、縦の＋で下に動きます。どの基準位置からも枠の縁を越えて文字を移せます。キー文字のサイズは65～140％で、長いキー名は移動前に枠幅に合わせます。
- **消費MP・アイテム所持数・チャージ数**　「配置・連打」で3種類をそれぞれ調整できます。各フォントは「自動（純正）」「AXIS」「Miedinger」「Trump Gothic」から選択でき、文字サイズは50～180％です。消費MPなどのコストは左下、薬などの所持数とアクションのチャージ数は右下に表示します。数字が長い場合やコストとチャージを同時に出す場合は、使える幅に合わせます。
- **リキャスト**　残り秒数はアイコン中央に表示します。「リキャスト文字サイズ」で65～140％に調整できます。アイコンは高解像度素材を優先します。
- **疑似枠の押下**　疑似HBの発光元は、選択して隠した元HBの同じ枠です。1キーを押し続ければ、コンボの技が変わっても疑似HBの1枠目が元HBの連打に合わせて光ります。元HBの押下通知・押下素材を優先し、通常枠に対応する技がない間も押下を表示します。元の押下素材が透明、枠外、取得待ちのときは、押したスキルアイコン自体を少し沈め、内側に丸い縁の光を描きます。キーを離すと元の位置・明るさに戻ります。連打の通知を得られない間は、キーまたはマウスを押している間だけ、設定した発光間隔で補います。
- **発光する通常枠**　表示中のHB1～10から選択HBを除いて照合します。現在の純正表示が一致する枠を優先し、強化解除などですでにアイコンが戻ったときは、同じ登録ボタンの純正変化も照合します。赤魔のエンリポスト・エンツヴェルクハウ・エンルドゥブルマンの3段は、それぞれ対応する基本技の登録枠を探します。通常HBの押下発光はゲームの枠上に表示します。前の押下が光っている間に同じ技をもう一度押す場合も、新しい発光を表示します。ゲームの発光が続いたままの場合は、そのアイコンの描画時にだけ明暗を付け、描画が終わったら元に戻します。
- **SE**　「純正HBの発光1回につきSEを1回鳴らす」がONのとき、画面内の通常枠で押下の表示が変わり、そのHBの描画が完了した時点で1音を鳴らします。キーを離した後の候補変更、発光フラグだけ立った場合、非表示・画面外、同じ発光の継続フレーム、疑似枠だけの押下は無音です。
- **隠した元HBの押下音**　「隠した元HBの押下SEを消す」は初期状態でONです。元HBの枠実行やボタンの発光・音声処理に結び付いたゲームの押下音を止め、WPHが表示枠を光らせる処理内の二重音も止めます。設定画面の「トラブル時の診断」にある「元HBで抑止」で回数を確認できます。「枠不明の同音」は呼び出し元を特定できなかった同じ音番号の回数で、メニューのクリックなども含みます。
- **連打**　内蔵の長押し連打は初期状態でOFFです。ONのときは、ゲーム側で選択枠の最初の操作があり、Windows上でもその枠の主キーと修飾キーがそろっている場合に連打を始めます。Shift・Ctrl・Altを途中で変えた場合は主キーを押し直します。ReActionが有効な間はReActionが連打を担当します。

## 意図せず迅速魔が出たとき

`/wprivate config` で **トラブル時の診断** を開くと、**直近の迅速魔** を確認できます。FF14が迅速魔（PvEの技ID 7561）の使用を受け付けた時刻と経路が、次の迅速魔またはログアウトまで残ります。「受付時 Shift / -」はFF14が使用を受け付けた瞬間のWindowsのキー状態です。先行入力では実際に押した時刻とずれることがあります。

| 表示 | 意味 |
| --- | --- |
| WPH内蔵連打 | WPHが長押しによる追加の実行をその枠に送りました。 |
| 疑似HBクリック | 疑似HBのマウス操作から実行されました。 |
| ゲーム／他プラグインの枠操作 | FF14の枠を通った操作です。HB番号・枠番号・登録技IDが表示されます。 |
| 選択HBのコンボ置換 | 選択枠の登録技から迅速魔への置換を観測しました。他のコンボキーを押した場合にも起こります。 |
| 枠外・呼出元不明 | 対応する枠操作を観測できませんでした。呼び出したプラグイン名までは識別できません。 |

枠が光っただけのときやリキャストで入力が拒否されたときは、記録を更新しません。

## 詠唱・GCD中の先読み

通常HBの連打表示は、選択した疑似枠に対する実際の先行入力を最優先し、次にWrathComboがその枠に返す次候補を使います。Aの詠唱中にBが判明したら、押している間は通常HBのB枠を発動前から繰り返し光らせます。Bの詠唱開始・発動時点でBへの連打を終え、次の候補が出たらその枠へ移ります。GCDやアニメーションロックの解除、詠唱の8割到達を待つ設定はありません。FF14が次の使用として同じ技を先行入力に受け付けた場合は、その技の枠を光らせます。

「配置・連打」の **詠唱・GCD中の技順の先読み** は初期状態でONです。WrathComboが進行中の技を返し続ける間は、同じジョブ・選択枠・登録スキル・対象で、直前2技から同じ次の技へ続いた実績が3回あると、その通常枠を仮表示します。分岐を一度でも観測した並び、長い中断、ターゲット不一致は予測から外します。Procなどで初めて違う分岐が出る回は仮予測が外れることがあります。先行入力や新しい候補が判明したら発光先を更新します。十分な根拠がない間は次候補を待ちます。

技順はゲーム内で実際に受理した操作から、このセッションのメモリ上にだけ記録します。先読みをOFFにすると履歴を消し、実際の先行入力と現在候補だけで表示します。ジョブ・選択HBの変更やエリア移動でも履歴を消します。仮予測は疑似HBの実行アイコンやスキル選択に使いません。先読み先は、選択枠のキーやマウスを押している間に更新します。キーを離したら詠唱・GCD中でも次の連打は始まりません。ReActionがゲーム側のキー情報を消費していても、Windowsで同じ実キーの長押しを確認できる間は先読みします。長押しを確認できず、外部から新しい枠操作だけを受け取った場合は、その操作1回分を表示します。

## ゲーム内での確認

1. 木人の前で、選択HBにWrathComboを使う枠を置きます。出てくる技の基本アイコンを、画面に表示した通常HBにそれぞれ置いてください。
2. 赤魔の近接ではリポスト、ツヴェルクハウ、ルドゥブルマンを通常HBの別々の枠に置きます。強化3段を順番に使い、通常枠の発光も1段目、2段目、3段目の順に移るかを確認できます。
3. 詠唱ジョブでは選択枠のキーを長押しします。同じ木人で技順を繰り返したあと、設定画面の「トラブル時の診断」にある「直近の詠唱中の切り替え」に進捗率、技ID、判定理由が表示されます。「実績からの仮予測」と「選択枠の現在候補」をここで見分けられます。

## 確認範囲

設定画面の「トラブル時の診断」を開くと、疑似枠への直近の入力、発光要求と描画確認、SEの記録を確認できます。通常利用時は折りたたまれています。

模擬HUDで元HBの同じ1枠に16msごとに56回の通知を与え、素材が透明・未取得・枠外の各条件で、明るい背景と暗い背景に重ねた内側の光の画素を比較しました。連打中は明暗を繰り返し、離鍵後の再点灯は0回でした。押下素材と補助テクスチャの両方を使えない場合も、描画するアイコンの位置と濃さが押下ごとに変化し、隣の枠は動かず、離鍵で戻ることを確認しています。

通常HBについては、模擬HUDで詠唱・GCD待ちに次の技の発光7回とSE7回が対応し、疑似枠だけの押下によるSEは0回でした。FF14実機での純正との見比べとOBS録画・録音は未確認です。

## GitHub用ソースとビルド

**WPH210.zip** にはビルド済みDLLが入っています。**WPH210_GitHub.zip** にはソース、ビルドスクリプト、自動テストが入っています。

本体はWindows x64、Dalamud API 15、.NET 10向けです。.NET 10 SDKとDalamudの開発用参照を用意して `build_on_windows.cmd` を実行すると、`DevPlugin` にDLLとマニフェストが作成されます。開発用参照の標準パスは `%APPDATA%\XIVLauncher\addon\Hooks\dev` です。参照ファイルを別の場所に置く場合は `DALAMUD_HOME` にDalamud.dllのあるフォルダーを指定します。

GitHub用ZIPのルートで次のコマンドを実行すると、ゲームの代わりに同梱の模擬環境で、プラグイン本体の処理を確認できます。

```text
dotnet run --project Tests/Routing/Routing.csproj -c Release
dotnet run --project Tests/WrathLink/Compatibility.csproj -c Release
```
